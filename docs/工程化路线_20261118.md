## 0. 目标与非目标

**目标**：把“故障注入 → 处理暴露核验 → 可靠性判决 → 输出弃权”从 FAST-LIVO2 的进程内实现，拆成可被至少三个 LIVO 算法复用的监督层；算法原则上不改源码，只做话题/配置适配。三个算法初步定为 FAST-LIVO2（已有主实证）、R3LIVE（事件层复用 + clean exp18 接入）、LVI-SAM（clean exp18 接入，2 P0；VINS 反复 reboot，只证明 LIO→supervisor 发布链）。

**非目标**：
- 不提出新的有害更新判别器，不改 W16 判决逻辑与阈值；
- 不把输出弃权说成定位精度提升；
- 不在没有实测的情况下写端侧/实时性/跨平台结论；
- 本轮不消耗剩余 9 P0。

### 1.2 R3LIVE 现状（截至 2026-11-18）

R3LIVE 不是“只有文献引用”，而是已经完成第二系统的事件层复用；但它**没有接入 W16 判决与输出弃权**。

- 源码固定 `hku-mars/r3live` 提交 `6143a385…`；Hilti22 适配包括 LiDAR 轴变换、鱼眼→针孔重映射、HILTI 杆臂/外参补丁；构建带 `-DR3LIVE_HILTI22_ADAPTER=ON`，构建树 `~/catkin_r3live_ws`，二进制 `r3live_mapping` 存在。
- 运行验收：4 次额度，3 臂有效（exp18 开视觉、exp18 关视觉、exp14 内容滞后 0.30 s），exp14 正常臂因额度裁减未跑；另有 1 次无显示环境的技术失败。
- P2 跨系统臂 36 行已完成（M18/M20/M21/M22），事件表数据行 36/36 与 FAST-LIVO2 逐字节一致（6 对 L12 仅表头回显不同）；视觉写回随持续丢帧比例单调下降（exp18 1088→1046、exp14 736.7→696.7），证明“视觉确实参与位姿”。
- 精度层不成立：exp14 1 s RPE 0.0286→0.0291（无上升），exp18 干净运行 0.106/0.825/0.145（8 倍跨度），无法与运行间波动分辨；按既有口径不报精度。
- 安全机制层为空：R3LIVE 源码树无 `safetyRelState`/`SAFETY_HOLD_OUTPUT`/`safety_risk` 引用；没有 exp15 恢复段，没有安全状态 CSV，也没有在线弃权。它可以作为 Level A 的第二个算法，但需要外部 supervisor 才能补上机制复用证据。

### 1.3 主要缺口

1. **判决与弃权仍嵌在 FAST-LIVO2 进程内**：`ReliabilityMonitor` 是 header-only，但 `hold` 逻辑在 `LIVMapper::publish_odometry()`，第二个 LVI 无法直接复用。
2. **没有可复用接口**：输入仍是 VIO 内部量（`outage_frames`、`lidar_pts`、`rel_state`），没有“图像/ LiDAR / 位姿”级别的话题契约。
3. **测试未接入构建**：`test/` 下 4 个测试各有 `main()`，但 `CMakeLists.txt` 没有 test target，也没有一条命令跑全部测试。
4. **没有发布包**：无版本清单、无干净构建脚本、无 `REPRODUCE.md`、无容器/依赖锁定；实验脚本依赖 `~/experiments` 的绝对路径。
5. **三个 LIVO 的复用证据不齐**：FAST-LIVO2 有机制证据，R3LIVE 只到事件/验收层，LVI-SAM 只到 clean 接入/发布链（538 条全 OK，VINS 反复 reboot）；尚无“零源码修改接入”的完整三算法机制证据。

## 2. 目标架构

```
图像 / LiDAR / IMU ──> 任一 LVI 算法 ──> 原始位姿 (odom)
        │                    │                 │
        │                    └── 可选诊断 ─────┤
        ▼                                      ▼
  健康观测（帧间隔、点云点数）        safety_supervisor
        └──────────────> safety_core <────────┘
                         │ 状态：正常/降级/不可用
                         │ 决策：接受/保持
                         ▼
                  /safety/state
                  /safety/odom（弃权后的位姿）
```

**分层**：

- `safety_core`：C++14，无 ROS、无 Eigen 依赖（或仅 header 级），包含
  - `ReliabilityMonitor`（现有 W16 状态机，原样迁移）；
  - `OutputGate`（新：最后可信位姿缓存、UNKNOWN 保持、OK 释放、事件记录）；
  - `Decision`/`FrameHealth` 数据结构与配置解析。
- `safety_ros`：ROS1 Noetic 薄封装
  - `supervisor_node`：订阅图像、点云、原始 odom；计算帧间隔与点数；调用 core；发布 `/safety/state` 与 `/safety/odom`；
  - 不广播 TF（TF 仍由 LVI 负责），避免双发布者冲突；下游改用 `/safety/odom`。
- `camera_fault_injector`：保持独立，作为可复用注入前端。
- `eval`：统一离线评估 CLI（复用 `ape_unified.py` 的对齐逻辑），输入 TUM + 事件表，输出 APE/RPE/包络/状态统计。

**两种接入级别**：

- **Level A（算法无关，优先）**：只读话题，不改 LVI 源码；用图像帧间隔与 LiDAR 点数驱动 W16；输出弃权由外部节点完成。第二个 LVI 只需 remap。
- **Level B（可选，诊断增强）**：算法通过 plugin/诊断话题提供 `n_eff`、视觉位置修正量等内部量；用于更新层准入研究，不作为复用性必需条件。

## 4. 接口草案

```cpp
struct FrameHealth {
  double stamp = 0.0;
  bool has_image = false;
  bool has_lidar = false;
  int lidar_points = 0;
};

struct Pose {
  double t = 0.0;
  double p[3] = {0, 0, 0};
  double q[4] = {0, 0, 0, 1};  // x,y,z,w
};

struct GateOutput {
  bool hold = false;
  Pose pose;          // hold 时为最后可信位姿
  const char* reason; // 便于日志，不参与控制
};

class OutputGate {
 public:
  explicit OutputGate(const GateConfig& cfg);
  GateOutput update(RelState state, const Pose& raw);
};
```

配置只保留可解释字段：`n_outage`、`n_deg`、`n_unk`、`n_lidar_unk`、`n_res`、`lidar_p05`、`lidar_p50`、`hold_output`。阈值文件仍用现有 v2 格式，不新增格式。

## 5. 三个 LIVO 的分工与最小复用证据

| 算法 | 融合架构 | 现有基础 | 还缺什么 |
|---|---|---|---|
| FAST-LIVO2 | 直接光度 + 顺序滤波 | W16/输出弃权/恢复准入全部在本系统；104 矩阵、8 次回放、exp15 案例 | 把核心抽成外部 supervisor 后可继续作为参照实现 |
| R3LIVE | ESIKF + RGB 点云 | Hilti22 适配、36 行事件层复用、视觉参与直证 | 外部 supervisor（W16+弃权）、一次 exp15/退化段、manifest |
| LVI-SAM | 因子图（VIO + LIO） | 源码已取、构建成功、Hilti22 点云/相机适配、clean exp18 已完成（2 P0，538 条全 OK；VINS 反复 reboot） | W4c 退化段、三算法 manifest；外参/时间方向仍需轨迹验证 |

**最小复用证据**（每算法，不是全矩阵）：
- 一次干净运行 + 一次退化/注入运行；
- 能输出 `/safety/state` 与 `/safety/odom`；
- 记录状态切换、弃权包络、恢复次数；
- 只改 launch/remap 与配置，不改算法源码。

不要求三算法精度可比，不写“跨算法泛化”结论；三算法只证明“机制可接入、事件层可复用”。若要做三算法同口径的剂量/精度矩阵，需要另立预登记与预算。

**预算含义**：截至 W4c 总账 291/300，剩 9（D 1 + G 8）。W4a 用 3、W4b 用 2、W4c 用 12；剩余 9 不足以做三算法完整剂量/精度矩阵；W5 已完成（0 P0）。若要做同口径矩阵，需另立预登记与预算。
